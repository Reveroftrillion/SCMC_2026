# CTRL 제어 재구현 0단계 명세와 첫 조향 계산

작성일: 2026-10-25. 기준 main: `6c2d9a2`. 전체 순서는 [재구현 계획](INDEPENDENT_REBUILD_PLAN_2026-10-25.md)을 따른다.

## 이번 작업의 완료 범위

제어 입출력 계약과 미션별 평가 항목을 정의하고, ROS와 독립적인 첫 조향 계산을 작성한다. 새 모듈은 기존 제어기·경로 helper·모델을 import하지 않는다. 기존 launch에서 활성화하지 않으며 실제 송신 경로 연결은 후속 작업이다.

0단계의 **명세 작성**과 자산 목록 작성은 이번 범위다. 차량 기하/조향 응답의 재측정, 자산 사용 근거 확보, 현재 MORAI 성능 측정과 최종 배포용 합격선 확정은 아직 열린 항목이다. 따라서 0단계의 현장 확인까지 모두 완료했다고 표시하지 않는다.

## 좌표·단위·시간 계약

| 항목 | 새 계산 모듈의 계약 | 기존 시스템과 연결할 때 확인할 사항 |
| --- | --- | --- |
| 차량 위치 | 후륜축 중심의 평면 위치, m | 현재 localization은 `map`/`base_link`로 발행. 실제 센서 장착점과 후륜축 관계 재확인 |
| 차량 좌표 | x 전방, y 좌측 | 센서 좌표는 변환 완료 후 전달 |
| yaw | +x에서 반시계 방향, rad | IMU 진북/지도 격자북 보정은 localization의 책임 |
| 속도 | 전진 0 이상, m/s | 후진 입력은 첫 구현에서 거부. km/h 변환은 경계에서 한 번만 수행 |
| 조향 | 가상 앞바퀴의 자전거 모델 조향각, 좌회전 양수, rad | 핸들 각도나 MORAI 정규화 명령과 구별. 변환/보정은 별도 담당 |
| 경로 | 방향이 있는 평면 polyline, 차량과 같은 frame | 경로 형상과 진행 방향을 호출자가 확정 |
| 새 경로 거리 | 첫 점부터 누적한 polyline 길이, m | `global_s`와 다르다. 원점/연결 경로/전역 station 변환은 후속 경계 작업 |
| 시각 | `now_s`, pose 시각, reference 요청 시각은 같은 시간축의 초 | ROS 시각과 monotonic 시각을 섞지 않음. 시계 역행은 호출 경계에서 재초기화 |
| 계산 간격 | `0 < dt_s <= max_step_s` | 주기 누락을 큰 dt로 숨겨 조향 제한을 해제하지 않음 |
| 이전 조향 | 직전에 실제 채택한 목표 조향각, rad | 경로 변경 때에도 연속성을 위해 전달. 최초 값의 근거는 호출자 책임 |

입력 단위가 맞는다는 책임과 센서 신뢰도 판단은 호출 경계에 있다. 새 모듈의 `valid=True`는 조향 계산이 계약을 만족했다는 뜻이며 충돌 없음이나 주행 허가를 뜻하지 않는다.

## 첫 조향 모듈 API와 정책

구현: `src/ctrl_control/ctrl_control/ctrl_lateral.py`.

- `Polyline`: 식별자, 좌표계, 2개 이상의 점. 입력을 복사해 불변으로 보관한다. 연속 중복점/1µm 이하 구간, 비정상 수치, 잘못된 차원과 누적 길이 계산 불가를 거부한다.
- `VehiclePose`: 후륜축 위치·yaw·속도·시각·frame.
- `TrackingReference`: polyline, **추종 요청**의 시각, 위치 투영을 허용하는 시작/끝 station. static 지도 파일의 오래된 생성 시각을 매번 새 센서 시각처럼 바꾸지 않는다.
- `LateralConfig`: 차량 기하, preview 규칙, 조향각/변화율 한계, 입력 나이와 오차 한계를 명시적으로 받는다. 생산 차량용 숨은 기본값을 두지 않는다.
- `compute_steering`: 위 입력과 `now_s`, `dt_s`, `previous_angle_rad`로 불변 결과를 반환한다. 전역 변수, 누적 내부 상태, ROS, 소켓, 기존 CTRL helper 의존성이 없다.
- 실패 결과에는 `angle_rad=None`을 반환한다. 실패를 직진 0도로 해석하지 않는다. 감속·정지·인계는 향후 상위 제어기의 책임이다.

검색 구간은 경로상의 현재 구간을 호출자가 지정한다. 첫 호출에서 전체 경로를 허용할 수 있지만, 자기 교차/겹침에서 같은 거리의 서로 다른 station이 나오면 `ambiguous_projection`으로 거부한다. 닫힌 경로의 lap 구분과 진행 구간 갱신은 후속 경로 관리기의 책임이다.

예상 preview는 `min + speed * time`을 `[min, max]`로 제한한다. 투영점부터 이만큼의 **경로 길이**를 진행한 목표를 선분 보간으로 선택한다. 경로 끝에서는 목표를 끝점으로 제한하며, 목표가 차량 뒤/측면에 있거나 사실상 차량과 같으면 유효 명령을 내지 않는다.

차량 좌표의 목표가 `(x_t, y_t)`일 때 후륜축에서 목표까지 가는 접선 원의 곡률은 `2*y_t/(x_t²+y_t²)`이고, 자전거 모델 조향은 `atan(wheelbase*curvature)`다. 분모에는 실제 목표까지의 직선거리를 사용한다. 경로 길이 preview를 분모로 대입하지 않는다. 각도 제한 후 `max_rate * dt`만큼으로 이전 조향에서의 변화도 제한한다. 제한 여부와 제한 전 값을 함께 반환한다.

이 기하적 방법의 참고 자료는 R. Craig Coulter, *Implementation of the Pure Pursuit Path Tracking Algorithm*, CMU-RI-TR-92-01, 1992, §2–3이다. [CMU 원문](https://www.ri.cmu.edu/pub_files/pub3/coulter_r_craig_1992_1/coulter_r_craig_1992_1.pdf). 원문의 좌표 표기와 여기의 전방 x/좌측 y를 구분한다. 경로 길이 preview, 명시적 검색 구간, 실패 결과와 제한 정책은 이번 요구사항에서 정했다. 다른 팀 구현을 검토한 이력은 [전체 계획](INDEPENDENT_REBUILD_PLAN_2026-10-25.md)에 기록돼 있다.

## 구현 전 고정한 검사 기준

### 해석 가능한 기하·입력 계약

- 직선 중심에서는 조향 0. 좌우 반사는 조향/횡오차 부호를 반전하고 크기를 유지.
- 같은 장면의 평행 이동/회전으로 조향이 바뀌지 않음.
- 원 위의 목표에서는 알려진 반지름으로 구한 `atan(wheelbase/radius)`와 일치. 원형 polyline의 꼭짓점에 목표가 오도록 구성해 경로 길이와 chord의 차이도 검사.
- 선분 안의 위치 투영과 목표 보간, 짧은 경로 끝 처리, 검색 구간과 자기 교차 모호성 검사.
- 각도와 변화율 한계를 모든 유효 출력에서 만족. 경로 식별자가 바뀌어도 이전 명령에서의 변화율을 유지.
- NaN/inf, 좌표계 불일치, 후진, 잘못된 dt, 미래/만료 시각, 과도한 경로/방향 오차를 거부. 경계의 허용/거부 조건을 함께 검사.
- 입력 점 배열의 사후 변경이 경로를 바꾸지 않고, 같은 입력은 같은 출력을 냄.

### 폐루프 합성 검사

검사 정의는 `tools/lateral_cases.json`에 먼저 고정한다. 차량 모델은 지연·미끄러짐 없는 자전거 모델이며, 매 step의 일정 조향에 대한 원호 적분으로 위치를 갱신한다. 오차 정답은 직선/원의 식/사인 경로 식으로 독립 계산한다.

| 장면 | 조건 | 사전 합격선 |
| --- | --- | --- |
| 직선 6개 | 속도 2/6/12m/s × 초기 좌우 0.8m, 12초 | 최대 횡오차 ≤1.0m, 마지막 2초 RMS ≤0.10m, 최종 ≤0.10m |
| 원 2개 | 반지름 25m, 좌/우, 속도 6m/s, 초기 안쪽 오차 0.5m, 12초 | 최대 반지름 오차 ≤0.8m, 마지막 2초 RMS ≤0.20m, 최종 ≤0.20m |
| 사인 2개 | 진폭 ±3m, 주기 60m, 속도 6m/s, 초기 오차 ±0.8m, 18초 | 최대 수직 오차 ≤1.2m, 마지막 2초 RMS ≤0.35m, 최종 ≤0.35m |

공통 `dt=0.02s`, wheelbase=2.8m, preview min/max/time=4m/12m/0.6s, 조향 한계 0.5rad, 변화율 0.8rad/s다. 전부 합성 검사용 값이며 현 차량 튜닝값이 아니다. 유효 결과만으로 끝까지 수행하고 각도/변화율 제한 위반이 없어야 한다. 계산 시간 분포는 측정하되 Windows 관측치를 실시간 보장으로 쓰지 않는다.

검사 실패가 발생하면 실패 로그와 요구사항을 보존하고 원인을 확인한다. 단순 통과를 위해 위 기준을 바꾸지 않는다. 실제 모델에 맞지 않는 요구사항이 확인되면 별도 설계 변경으로 기록한다.

## 자산 출처 확인과 후속 연결 조건

현재 경로별 SHA256·기준 Git blob·미확인 항목은 `independent_assets_2026-10-25.json`에 새 목록으로 저장한다. 목록은 소유권/사용 허락의 증명이 아니다. 기존 원본/리소스 manifest는 갱신하지 않는다.

모델과 학습 데이터, 지도와 경로/체크포인트, 신호 보정, 곡률 캐시, 센서/차량 보정과 도구의 출처를 각각 확인한다. 외부 제공물이면 제공 근거를, 자체 생성물이면 생성 절차·입력을 남긴다. 확인 전에는 최종 배포 자산으로 승인된 것으로 표시하지 않는다.

후속 실행 연결 전에 일반 경로, 회피 오프셋/chain, local reference의 변환과 station 대응을 검증한다. 기존 `Route` 또는 controller를 쓰는 연결부는 의존성 목록에 남긴다. Linux catkin 설치/메시지, 기록 재생, 제어 없는 병행 계산, 별도로 승인된 MORAI 주행을 통과해야 실제 제어기를 교체 완료로 처리한다.
