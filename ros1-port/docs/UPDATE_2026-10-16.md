# GitHub 코드 갱신 및 실행 확인

목표: GitHub의 최신 ROS1 코드를 별도 로컬 브랜치에서 빌드하고 실행한다.
기존 `feat/ros1-port`를 보존하고 `origin/refactor/identifiers-docs`의
`2d34dc2`에서 `run/ros1-update-20261016`을 생성했다. production 수정은 없다.
GitHub push나 main 병합은 수행하지 않았다.

검증 범위와 완료 기준: Docker devel/install 빌드, native 메시지/TF,
adapter/packaging, launch 해석 및 drive=false 실제 실행을 확인한다.
센서 수신 성공은 별도로 판단한다.

결과:

- 식별자 역매핑 AST 검사: 10개 런타임 파일, 93개 식별자 PASS.
- Docker devel/install 빌드 및 환경 검사 PASS.
- 실제 메시지 직렬화/native TF 검사 PASS, adapter 27개와 packaging 8개 PASS.
- devel/install launch 노드 해석 PASS.
- drive=false 20초 실행: launch 기동 및 종료 성공, 제어 UDP9093 송신 0개.
- GPS/IMU/status/LiDAR/camera 수신 모두 0개. odometry와 behavior target도
  생성되지 않아 실제 센서 수신·판단 검사는 FAIL(exit 1). MORAI 실행과 센서
  Connect/포트 설정을 확인한 후 재검증해야 한다. 연결 부재의 원인은 확정하지 않았다.
- 전체 차등 비교/GPU 추론/주행은 이번 작업에서 수행하지 않았다.
  기존 신호 문제와 센서 동등성 등은 미해결 상태다.

새 결과는 Git 제외 경로 `ros1-port/docker/artifacts/update-20261016/`에 있다.
`workspace/exit-codes.json`, `live.json`, `live.launch.log`를 참조한다.
기존 결과는 덮어쓰지 않았다.

저장소 루트에서 센서 연결 후 제어 송신 없이 실행:

```bash
bash ros1-port/docker/run.sh --receive-root roslaunch docker/local.launch drive:=false
```

종료는 Ctrl+C. 실제 주행은 별도 지시 후 수행한다.
