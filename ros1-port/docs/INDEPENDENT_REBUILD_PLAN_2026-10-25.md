# CTRL 팀 단계별 구현·전환 계획 — 2026-10-25

CTRL 팀은 현재 완주 수준을 비교 기준으로 두고, 미션 요구사항과 입출력 계약에 맞춰 기능을 설계·작성한 뒤 순서대로 전환한다. 이름이나 함수 배치를 바꾸거나 기존 함수를 문장별로 옮긴 작업은 전환 완료로 세지 않는다. 이 문서는 진행 계획이며 실행 결과는 각 결과 문서에서 확인한다.

계획의 기준선은 main `6c2d9a2`다. 실행 진입 경로는 `ctrl_start.launch` → `docker/local.launch` → `src/ctrl_bringup/launch/ctrl_competition.launch`다. 현재 사용 중인 `ctrl_ros1` 호환 계층과 기존 helper 의존성도 단계별로 정리한다.

## 작업 범위와 반복 절차

- 미션 판단·제어·인지·위치 추정 및 관련 helper를 기능별 작업 목록으로 관리한다. 라이브러리, 프로토콜과 제공받은 자산은 제공 근거와 사용 조건을 함께 적는다.
- main과 기준 자료·이전 확인 결과를 대조 대상으로 유지한다. 기존 코드와 새 코드가 함께 쓰이는 동안에는 남은 범위를 밝혀 두고, 전체 전환이 끝났다고 표시하지 않는다.
- 검토한 기존 구현, 새로 작성한 부분과 남아 있는 의존성을 이력에 함께 적는다. 구현 경위와 다른 표현을 사용하지 않으며 설계 선택의 근거도 남긴다.
- 기능별 브랜치에서 작업하고 병합을 마치면 정리한다. GitHub push/main 병합과 제어 송신 시험은 사용자 승인 범위에서만 진행한다.
- 개발 순서는 의존 관계와 확인 난이도로 정한다. 뒤에 배치된 기능도 전환 대상이며, 자산 확인은 첫 단계부터 병행한다.

기본 작업 흐름은 **요구사항과 단위/좌표/시간 정리 → 계산 모듈 작성 → 독립 장면 확인 → 노드 연결 → 회귀 확인 → Linux 빌드·수신 확인 → 승인된 MORAI 시험**이다.

## 착수 준비: 평가 항목과 입력 기준

현재 완주 기록은 해당 장면의 근거로 사용한다. 모든 배치나 입력 오류를 확인한 결과로 확대하지 않는다. 10/24의 975 PASS/기존 4 FAIL은 당시 오프라인 결과이며 이번 계획에서 다시 실행한 값이 아니다.

- 정상 직선/곡선, 신호, 정적 장애물, 보행자, 로터리, 고속 구간, 터널, 종료 정지를 별도 평가 항목으로 만든다.
- 경로 횡오차의 분포/최댓값, 경계 이탈, 속도 초과, 정지 위치 오차, 최소 물체 간격, 충돌, 계산 시간과 제어 명령의 연속성을 기록한다. 수치 합격선은 구현 전에 도로·차량 조건과 기준 측정으로 정한다.
- 경로 진행거리의 원점과 차량 기준점, 좌표계, m/s와 km/h, 조향각과 명령 정규화 값, 센서 시각과 만료 규칙을 명시한다. `stop_s`와 차체 앞/뒤 기준점의 변환도 확인한다.
- 기존 테스트는 호환성 자료로 보존한다. 새 검사는 요구사항에서 만들고 기존 함수의 출력값만 정답으로 복제하지 않는다. 요구사항 변경이 필요한 실패는 별도 결정으로 남긴다.
- `best.onnx`는 원본과 동일한 것으로 확인했던 자산이다. 모델 README의 '사용자 제공' 문구만으로 팀 자체 학습을 증명하지 않는다. 학습 데이터·가중치 출처를 확인하고, 필요하면 사용 가능한 데이터와 모델로 다시 학습/평가한다.
- 지도·경로·체크포인트·보정값도 대회 제공물, 팀 측정물, 다른 팀 생성물로 구분한다. 출처가 확인되지 않은 자산의 최종 유지 여부는 보류한다. 숫자만 바꿔 새 자산으로 표시하지 않는다.

## 첫 구현 단위와 확인 순서

첫 작업은 906줄의 `ctrl_core.py`를 통째로 대체하는 방식으로 잡지 않는다. 패킷·경로·위치 추정·횡방향/종방향 제어가 함께 있으므로 기능을 나눠 해당 단계에서 전환한다.

먼저 ROS에 의존하지 않는 조향 계산을 작성한다. 알고리즘의 정의와 식을 근거로 설계하고 참고한 자료를 남긴다. 새 구현이라는 이유로 알고리즘 종류까지 반드시 바꿀 필요는 없다.

- 입력: 차량 위치·방향·속도, 명시된 차량 기준점, 검증된 참조 경로와 시각, 차량 기하와 조향 한계.
- 출력: 단위를 명시한 목표 조향각, 계산 유효 여부와 실패 이유. 정규화된 MORAI 명령으로의 변환은 별도 경계로 둔다.
- 먼저 검증: 직선의 좌우 대칭, 알려진 곡률의 곡선, 속도 변화, 중복/짧은 경로, 비정상 수치와 경로 전환. 목표점 선택·오차 계산·조향 제한을 각각 확인한다.
- 그다음: 간단한 차량 모델로 폐루프 추종을 확인하고, 기록 입력에서 계산 결과·변화율·실행 시간을 관찰한다. 기록 재생만으로 새 제어기가 실제 차량을 잘 움직였다고 판정하지 않는다.
- 연결: 초기에는 새 계산을 병행 기록하고 제어 출력은 기존 경로만 사용한다. 실제 교체 전에 일반 경로·회피 오프셋/chain·고속 local reference 세 입력 형태의 연결 계약을 확인한다.
- 첫 소단위 완료는 '새 조향 계산 검증'이다. 기존 `Route`나 참조 helper를 사용하는 동안 제어기 전체를 교체 완료로 표시하지 않는다.

## 미션별 확인 항목

### 정적 장애물

현재 `behavior.yaml`은 `avoid.static_course: true`다. `ctrl_static_course.py`에는 고정 배치의 사전 정보가 있다. 새 설계는 관측 물체와 도로 경계로 경로를 검증하며, 고정 배치를 사용한다면 그 정보의 제공 근거와 적용 조건을 별도로 명시한다. 예상 밖 배치를 만났을 때에도 우회 불가 정지가 성립해야 한다.

### 보행자

순간 속도만으로 정적 물체와 보행자를 바꾸지 않는다. 분류 불확실성, 횡단 중 정지, 관측 공백과 재진입을 명세한다. 새 구현의 재출발 조건은 사람의 경로 점유 여부와 관측 근거로 검사한다.

### 로터리·고속 구간

진입/차로 변경 시작만 검사하지 않는다. 실행 도중 앞차 감속, 뒤차 접근, 관측 상실로 계획이 더 이상 유효하지 않을 때 유지·감속·중단 조건을 정의한다. 통과 시간 단축은 충돌/경계 조건을 통과한 뒤 평가한다.

### 터널

`states/ctrl_tunnel.py`만 교체해서 터널 구현이 바뀌는 것은 아니다. 실제 회피는 `states/ctrl_avoid.py`와 경로 계획기·BEV·벽 관측·보행자 판단·위치 추정에 걸쳐 있다. 현재 설정의 터널 경로 계획기는 `simple`이다.

터널은 위치 추정·인지·정적 회피·보행자 모듈이 검증된 뒤 마지막 통합 미션으로 교체한다. 기존 지면 오탐·낮은 물체·초기 관측 공백·복귀 경로 실패는 새 검사의 요구사항으로 남긴다. 기존 보정 코드 복사를 재구현으로 계산하지 않는다.

## 병행 정리할 기반 구성

아래 구성은 미션 개발과 함께 정리하고 전체 작업을 마치기 전에 확인한다.

- 카메라: `ctrl_yolo_onnx.py`, `ctrl_yolo_signal_node.py`, `ctrl_stop_lines.py`의 입력/추론/판정/보정 구현과 모델·데이터 출처.
- 센서/통신: `ctrl_control/ctrl_bridge.py`, `ctrl_core.py`의 패킷 처리, 카메라·LiDAR bridge. 문서화된 프로토콜을 근거로 새 구현 또는 허용된 기존 구현의 의존성을 기록.
- ROS1: `ctrl_ros1/`의 자체 작성 부분과 외부 유래 부분을 구분. 새 모듈의 ROS 연결을 `rospy`로 직접 작성할지 결정하고, 단계별로 호환 계층 의존성을 줄임. 단순 ROS1 이식도 새 미션 알고리즘 개발과 구분.
- 인터페이스/패키징: 메시지, launch, catkin, Docker, 실행/기록 도구, 기본 설정과 실제 활성화 경로 확인. 교체된 모듈이 선택되지 않고 옛 코드만 실행되는 상태를 검사.
- 데이터: 지도, 전역 경로, 체크포인트, 신호 정지선, 곡률 캐시와 설정. 유지 가능한 근거 또는 직접 생성 절차를 기록.

## 작업 종료와 다음 인계

작업 단위마다 설계·코드·helper 의존성·독립 검사·빌드/연결 근거와 성능 측정/미검증 조건을 인계한다. 남아 있는 기준 구현·모델·데이터는 완료한 범위와 나눠 관리한다. 완료 여부는 이름이나 유사도 수치로 판단하지 않는다.

초기 착수 범위는 **0단계 제어 계약/평가 기준과 1단계의 첫 조향 계산**이었다. 이 계획을 처음 작성할 때에는 주행 코드·설정·모델·기준 자료·이전 기록을 바꾸거나 테스트·Linux 빌드·MORAI 주행·commit/push를 수행하지 않았다. 현재 진행 상황은 [요청 관리 결과](PATH_SELECTION_RESULT_2026-10-25.md), 다음 작업은 [작업 계획과 인계](DEVELOPMENT_WORKFLOW.md)를 따른다.
