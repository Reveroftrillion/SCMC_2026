01한눈에 보기

본질 인지 기반 자율주행이 아니다. HD맵(MGeo) 링크 경로를 정답으로 놓고 그 위의 waypoint를 기하학적으로 추종하는 규칙 기반 주행이다. 인지 결과는 perceptionResult로 이미 주어진 것을 소비할 뿐, 만들지 않는다.
횡방향 Pure Pursuit 계열이되 교과서 공식이 아니다. 방위 오차 θ에 대해 steer = −(θ + ½·sin2θ) — 작은 θ에서 이득 2배로 동작하는 변형.
종방향 목표 가속도에 시그모이드로 게이팅된 적분 보정을 더해 가속/제동 분기를 결정한 뒤, 각각 별도의 맵 함수로 페달값을 만든다.
속도–조향 결합 속도 지령이 거리 / cosh(π·θ) 형태다. 방위가 틀어질수록 속도가 쌍곡선으로 급감한다 — 코너에서 자동으로 감속되는 구조.
정지 임계값 비신호 교차로 정지선은 노드 3 m 앞, 일반 정지 타겟은 7 m 앞에서 잡는다.

02조사 방법과 난독화 우회

시뮬레이터 로직은 전부 Simulator_Data/Managed/Assembly-CSharp.dll에 들어 있다. 타입명·메서드명·필드명은 [[]][][]… 형태로 난독화돼 있어 소스 복원은 불가능하다. 다만 세 가지가 살아남았고, 그 틈으로 구조가 전부 드러난다.

  • 네임스페이스 — MORAI.ControlAlgorithm, MORAI.Decision 등은 그대로다.
  • enum 멤버명 — 직렬화 대상이라 이름이 유지된다. 상태기 전체가 여기서 나왔다.
  • Unity/BCL 호출 대상 — Mathf.Atan2, Mathf.Exp 같은 외부 호출은 난독화가 불가능하다. 수식의 뼈대가 여기서 나온다.

결정적 관문: 위조 상수 복제본

난독화기는 같은 구조에 가짜 상수를 채운 복제 메서드를 다량 생성해 둔다. 종방향 제어 메서드는 16개 사본이 존재하고 그중 진짜는 하나뿐이다. 구조만 보고 읽으면 100% 틀린 결론에 도달한다.

판별 기준은 상수의 물리적 타당성이다. 진짜 메서드에는 0.017453(π/180), 57.29578(180/π), 0.27778(km/h→m/s), ±180 같은 값이 나오고, 복제본에는 1537.0, 611.0, 893.0처럼 아무 의미 없는 수백~수천대 정수가 들어간다.

04횡방향 제어 법칙 코드 확인

입력은 목표점 위치, 현재 위치, 현재 yaw(도) 세 개. 출력은 (속도 지령, 조향 지령) 쌍이다. IL을 그대로 옮기면 이렇다. 

// MORAI.ControlAlgorithm.<obf> :: <obf>   [메서드 #420]
// wrapRad(x,lo,hi) = deg2rad(wrap360(x,lo,hi))  ← 헬퍼 #363, 라디안 반환

if (!this.enabled) return (0, 0);

curPos.y = 0;                                    // 평면 투영
Vector3 d    = this.targetPos - curPos;          // 목표점까지 벡터
float   dPsi = wrapRad(this.targetYaw - yawDeg, -180, 180);
float   dist = round(|d|, 3);                    // 목표점까지 거리 [m]
float   th   = wrapRad(atan2(d.x, d.z)*57.29578 - yawDeg, -180, 180);
                                                 // ↑ 방위 오차 θ [rad]
if (dist > 0.01) {
    A = clamp(dist, 0, this.maxRange) / cosh(PI * th);
    B = -clamp( sin(th)*cos(th) + th, -maxSteer, maxSteer );
} else {
    A = 0;
    B = -clamp( dPsi, -maxSteer, maxSteer );     // 도착 시 헤딩만 정렬
}
return (A, B);
정리하면 θ = wrap±π( atan2(Δx, Δz) − yaw )
조향 B(θ) = −( θ + ½·sin 2θ )
속도 A(θ, d) = clamp(d, 0, R) ⁄ cosh(π·θ)

sin θ·cos θ는 ½·sin 2θ와 같다. 따라서 작은 θ에서 B ≈ −2θ — 순수 비례 조향의 두 배 이득으로 시작해 θ가 커질수록 이득이 완만해지는, 부드럽게 포화되는 곡선이다. 부호가 음수인 것은 MORAI의 조향 부호 규약 때문이다.

조향 지령

B = −(θ + ½·sin2θ)

속도 게이트

1 / cosh(π·θ)

가로축은 방위 오차 θ(도). 속도 게이트는 θ=30°에서 이미 40%, 60°에서 9%까지 떨어진다 — 경로에서 벗어나면 사실상 멈춘다.

참고할 점: 별도의 속도 계획기 없이 조향 오차 하나로 속도를 깎는 구조다. 곡률이 큰 구간에서 목표점 방위 오차가 자연히 커지므로, 코너 감속이 공짜로 따라온다. 우리 쪽 EKF·경로추종에 그대로 쓰긴 어렵지만, 속도 프로파일의 폴백 로직으로는 참고할 만하다.

05종방향 제어 법칙 코드 확인

목표 가속도를 받아 accel / brake 페달값으로 배분한다. 16개 사본 중 물리 상수를 가진 진짜 하나가 아래다. 

// MORAI.ControlAlgorithm.<obf> :: <obf>   [메서드 #644]
// 인자: basis(Vector3), aDes(float), vel(Vector3, km/h), aux, gear

if (gear == 2) { vel = -vel; aDes = -aDes; basis = -basis; }   // 후진(R)

vel.z = 0;
vel  *= 0.27778;                       // km/h → m/s
float spd = |vel|;

float v = vel.x*basis.z + vel.y*basis.x;
v = (v != 0 && spd > 0) ? v / spd : 0;  // 헤딩 방향 정규화 성분

// 1 km/h 이하에서 감속 요구 → 적분 리셋 후 무출력 (정지 유지)
if (spd <= 0.27778 && aDes < 0) { this.integ = 0; return (0, 0); }
if (this.flagA == 1 || this.flagB == 1) return (0, 0);

float err = this.targetSpeed - v;
float u   = (this.k > 0) ? 0 : (1 - this.k);
float z   = 5.436563 * (u - 0.5);
float g   = exp(z) / (exp(z) + exp(-z));   // = sigmoid(2z), 0‥1
this.integ += err * g;                     // 게이팅된 적분

if (aDes + this.integ >= 0) accel = MapAccel(aDes, v, aux);
else                        brake = MapBrake(aDes, v, aux);

return (accel, brake);

핵심은 두 가지다. 첫째, 적분항이 페달값에 직접 더해지지 않는다. 적분기는 오직 가속이냐 제동이냐의 분기만 결정하고, 실제 페달값은 aDes 원본을 맵 함수에 넣어 얻는다. 가·감속 전환 근처의 채터링을 막는 히스테리시스로 동작한다.

둘째, 적분 이득이 상수가 아니라 시그모이드 게이트다. 5.436563 × 2 ≈ 10.87이 시그모이드의 기울기이고, u = 0.5가 중심점이다. u가 0/1일 때 게이트는 각각 0.004 / 0.996으로, 사실상 부드러운 on–off 스위치다.

MapAccel과 MapBrake는 서로 다른 메서드이며 시그니처는 같다 (aDes, v, aux). 내부까지는 복원하지 않았다 — 가속도→페달 역모델(속도 의존 룩업)일 가능성이 높다. 추정

09Q 키의 정체 미확정

어셈블리 전체에서 Input.GetKeyDown 호출 44곳을 전수 조사했다. Q를 쓰는 곳은 전부 카메라 컨트롤러와 서드파티 데모 에셋이었다 — freeCamera, ExtendedFlycam, SimpleCameraController, RTG 튜토리얼, OnlineMaps 데모. 자율주행 토글은 여기 없다.

대신 시뮬레이터는 데이터 기반 단축키 시스템을 쓴다: HotKeyDataSet, HotKeyInfo, _keyMappings, InitHotKeyDatas, GetHotKeyDatas. UI 쪽에는 DlgHotKeyCategory, Dlg_HotKeyItem이 있으므로 인앱 단축키 목록 다이얼로그가 존재한다.

한편 OnClickCruiseMode, ChangeEgoCruiseMode, IsEgoCruiseMode, m_toggleCruise가 있어 자율주행 진입점은 Ego Cruise Mode 토글로 보인다. Q가 이 토글에 매핑돼 있는지는 단축키 테이블을 열어야 확정된다.

확인 방법: 시뮬레이터 실행 → 단축키 목록 창을 열어 Q 항목을 직접 확인하는 것이 가장 빠르다.

  • 필드 의미는 대부분 미상. maxSteer, maxRange, targetSpeed 같은 이름은 사용 맥락에서 붙인 것이고, 실제 필드명은 난독화돼 있다.
  • 실측 파라미터 값 없음. 게인·lookahead 거리의 구체적 수치는 MonoBehaviour 직렬화 데이터에 있으나 필드명도 난독화돼 있어 어느 값이 무엇인지 대응이 안 된다.
  • #420이 어디서 호출되는지 미추적. 호출 그래프를 따라가면 Ego 전용인지 NPC 공용인지 확정할 수 있다.

규정 관련 — 반드시 확인할 것

시뮬레이터 내장 로직을 분석해 참고하는 것과, 내장 주행 기능이나 그 MGeo 링크 경로를 대회 주행에 직접 이용하는 것은 전혀 다른 문제다. 이 문서는 전자를 위한 기록이다. HD맵은 대회측이 제공한 것을 쓰되, 여기 적힌 수식·임계값을 그대로 이식하기 전에 규정의 해당 조항을 확인할 것.
