## 1. 절대 규칙 (위반 = 실격)

### 허용 UDP 채널 (v1.1 기준, 이것만)
1. **Ego Ctrl Cmd** (Sim ← User): Accel, Brake, Steer, Gear, CtrlMode
   - **cmd type 1번 (accel, brake)** / **ctrl mode 2번** 만 허용
2. **CollisionData** (Sim → User)
3. **Competition Vehicle Status** (Sim → User)
4. GPS / 5. IMU / 6. Camera / 7. 3D LiDAR

### 금지 (사용 시 실격)
- **Object Info** (`MoraiObjectInfoPublisher`, 포트 7605 관측) — 주변 객체 GT. 절대 수신·사용 금지.
  객체는 라이다·카메라로 직접 검출.
- **Ego Vehicle Status** (`MoraiInfoPublisher`, 포트 910/911) — 위치·타이어 포함 전체판. 금지.
  반드시 Competition Vehicle Status(축소판)만 사용.
- **TrafficLight Status / TLCtrlSubscriber** — 신호 GT. 금지. 신호는 카메라로만 인식.
- 시뮬이 이 채널들을 쏘더라도 **우리 코드가 받지 않으면 됨** (시뮬에서 못 꺼도 무방).

### 기타
- 시뮬과의 통신은 **순수 UDP만**. MORAI "ROS 연결"(rosbridge) 사용 금지.
  → UDP 직접 파싱 → ROS2 토픽 재발행 브리지 자체 구현. 내부 ROS2 사용은 자유.
- 대회 당일 **코드 수정 불가** (제출 후 파라미터·주석 포함). IP/포트는 설정파일·인자로 분리.
- 코드 유사성 검토 있음.

- 맵: **ENU**, 위치 기준점 = **후륜축 중심 (base_link)** ← Q&A 확정
- GPS: NMEA(GPGGA/GPRMC) → 십진도 → UTM52N(EPSG:32652) → 로컬
  ```
  map_x = UTM_x - 302595.0
  map_y = UTM_y - 4124145.0
  ```
  (NMEA ddmm.mmmm 양자화 스텝: 위도 ~0.19m/경도 ~0.15m. 노이즈는 없음 — 아래 참조)

- LiDAR: VLP16, X=Forward/Y=Left/Z=Up(ISO), 원점=마운트 위치. velodyne_pointcloud로 변환 가능

## 4. ★ 센서 노이즈 — 전 센서 무노이즈 확정 (핵심)

**2026년 한시적으로 GPS·IMU에 노이즈를 인가하지 않는 것으로 확정** (중간점검 후 심사위 결정,
규정집 v1.1 반영). 카메라·라이다는 원래 무노이즈. **→ 모든 센서가 무노이즈.**

**설계 함의:**
- EKF가 "노이즈와 싸우는 필터"에서 "주기 맞추고 부드럽게 잇는 가벼운 필터"로 축소.
  GPS는 거의 참값 위치, IMU는 거의 참값 자세를 제공. R/Q 튜닝 부담 대폭 감소.
- 남는 오차원: GPS NMEA 양자화(~0.19m 스텝), GPS(30Hz)/IMU(50Hz) 주기 차이, 순간 끊김 정도.
- **로컬라이제이션 난이도가 "GPS 음영구역 하나"로 집중.** 나머지 구간은 GPS를 거의 그대로 신뢰 가능.
- **단, GPS 음영구역 Blackout 미션은 원안대로 유지** (노이즈와 무관).

| 0 | 출발 (P→D + AutoMode=2 전환 필수) | 전환 누락 = 출발 실패 |
| 0~109 | 출발 판정 (60초 내 5% 통과) | 미통과 시 해당 차시 실패 |
| 208/315/436/550/610 | 신호 교차로 5곳 | 위반 각 15초 |
| 329 | 정적 장애물 (2×3×2m) | 충돌 15초. 신호(315)와 14m → 병렬처리 |
| 460 | 보행자 (10km/h 횡단, 감지15m) | 충돌 15초 |
| 890 | 회전교차로(끼어들기, NPC 20km/h 5초주기) | 충돌 유의 |

| 1881~1998 | **GPS 음영구역(터널 118m)** | GPS차단. 차로준수 채점 면제. 라이다 벽면정합 |
| 1998~2185 | 출구→결승 (186m) | 출구 노출폭주 주의 |

### 속도제한 예외구간 (v1.1에서 링크 ID로 명확화)
- **A2256W000411 시작점 ~ A2256W000153 끝점** (고주로 진입 ~ 톨게이트)

## 6. 미션별 채점 (규정집 3-2)

- **출발**: 1분 내 5%(109m) 통과 = 성공, 미통과 = 차시 실패
- **속도제한**: 60kph 초과 즉시 15초, 3초 지속마다 +15초 (예외구간 제외). 주최측은 Ego Vehicle
  Status로 판정, 우리는 Competition Vehicle Status(vel_x)로 자체 관리
- **교차로 신호**: 앞바퀴가 정지선 넘는 순간 신호로 판정, 미준수 15초. 신호=카메라 인식만
- **차로 준수**: 차선(실선·중앙선) 접촉 3초 지속마다 5초 (바퀴 1개 기준)
- **장애물 회피**: 충돌당 15초 (CollisionData 판정, 재충돌 시 추가)
- **끼어들기**: NPC 충돌 유의 (별도 성공 기준 명시 없음 → 충돌 회피가 목표)
- **GPS 음영**: GPS Blackout, **차로준수 채점 면제**
- **랜덤 미션**: 음영구역 내 임의 위치에서 장애물회피/끼어들기 중 출현
- **날씨/시간**: 구간별 랜덤 (Sunny/Foggy, 11/13/15시) → 조도 강건성 필수
- **제한시간**: 15분, 초과 시 차시 실패

### 순위 산정 (v1.1)
- 총 주행시간 = 실주행 + 패널티. **완주팀은 2회 중 짧은 쪽.**
- 미완주팀: ①체크포인트 달성도 ②총 주행시간
- **완주팀이 미완주팀보다 항상 우선순위** (v1.1 신규 명시)

## 7. Competition Vehicle Status 상세 (Q&A 확정)

### 포함 필드
차량 자세 정보, **x방향 속도(vel_x)**, 각속도, 제어 입력값(accel/brake/steer/gear/ctrl_mode) 등

### 제외 필드 (Ego Vehicle Status 대비)
pos_x/y/z (위치 없음!), vel_y/z, accel_x/y/z, tire_lateral_force_fl~rr,
side_slip_angle_fl~rr, tire_cornering_stiffness_fl~rr

→ **위치가 없으므로** GPS+IMU+속도로 EKF 추정 필수 (GPS 음영구역 미션의 존재 이유).

### 수신 방법 (Q&A 확정)
- 예제 `MORAI-NetworkModule/EgoNetwork/Publisher/EgoVehicleStatus.py` (24.R2.0 브랜치) 활용
- **시뮬레이터와 코드의 PORT 번호 통일 필수**
- **우분투 환경에선 PORT를 4자리로 변경 후 사용**
- ⚠️ **차량이 활성/주행 상태일 때만 유효값** (정지 시 0으로 보일 수 있음). 설정 변경 후엔

- **센서 Hz 불일치는 규정 위반 아님** (Q&A): 시뮬 FPS에 송신주기가 따라가서 설정15Hz→실제30Hz 등
  발생 가능. 허용 최대(30Hz) 안 넘으면 무방
- **성능 경고 (v1.1 신규)**: 판정+녹화 프로그램이 Client PC 부하 유발 → 데이터 전송 지연 가능.
  **센서 사양 낮추거나 코드 경량화 권장**. 팀 PC 지연은 운영측 미고려.

## 9. 아키텍처 (6블록, 웨이모식 모듈형)

```
[0]브리지 → [A]로컬라이제이션 / [C]카메라인식 / [D]라이다인식 → [E]플래닝 → [F]제어
```

- **[A] 로컬라이제이션**: 경량 EKF(GPS+IMU+vel_x). 전 센서 무노이즈라 튜닝 부담 적음.
  평상시 GPS 거의 그대로 신뢰. **음영구역만 라이다 벽면정합+추측항법.**
  초기 pose는 공식 체크포인트 좌표로 초기화. Re-Spawn/복귀 시 강제 재초기화.
- **[C] 카메라**: 차선 + 신호색. 날씨/시간 랜덤 강건성. 4번 망원카메라(신호 원거리 래치) 검토.
- **[D] 라이다**: 객체검출 + 음영구역 벽면추출. velodyne_pointcloud 활용.
- **[E] 플래닝**: Behavior FSM(병렬 — 신호315+장애물329 동시처리) + 지역경로 + 비용함수.
- **[F] 제어**: Kinematic Bicycle. **Pure Pursuit/Stanley 우선, MPC 옵션** (20Hz 위태로워 견고성 우선).
  출발 시퀀스: P→D + Keyboard→AutoMode(2) 전환 → Vehicle Status로 성공 확인 후 주행.
  정지 유지 시 brake 능동 인가(크립 방지).
- 인식 입력·GPS·IMU 전부 무노이즈 → 불확실성 관리 부담 최소.
- **성능**: 최소 20Hz 목표(보장 아님). 센서별 독립 스레드 수신 + 제어루프 논블로킹 read 필수.

### 7명 역할
브리지 2 / 로컬라이제이션 1 / 카메라 1 / 라이다 1 / 플래닝 1 / 제어+맵 1
(브리지가 병목 → 두껍게. A·C·D는 브리지 완성 전 mock으로 병렬 개발)
