# 0. 전체 그림 (3분 요약)

## 대회가 뭔가
MORAI 시뮬레이터 K-City에서 아이오닉5로 **2.2 km 한 바퀴**를 도는 대회. 빨리 가는 게 아니라 **패널티(신호위반·충돌·차선이탈) 안 받고 15분 안에 완주**하는 게 목표. 시뮬 PC와는 UDP로만 통신하고, 위치·주변 차량·신호의 "정답값"을 주는 채널은 쓰면 실격.

## 지금 어디까지 됐나
- 노트북에서 UDP로 차를 움직이고, GPS+IMU로 내 위치를 알고, 전역 경로를 5 km/h로 따라가는 **"눈 감고 경로 따라가는 차"** 가 완성됨.
- 미션(신호등·장애물·보행자·터널)은 **하나도 없음**. 이걸 3팀이 나눠서 붙인다.

## 어떻게 나누나
```
             ┌──────────────── 팀 1 「신호」 ────────────────┐
             │  카메라로 신호등 색 보고 정지선에 서기          │
             └──────────────────────┬───────────────────────┘
             ┌──────────────── 팀 2 「장애물」 ──────────────┐
             │  라이다로 장애물·보행자·NPC 보고 피하기/기다리기  │
             └──────────────────────┬───────────────────────┘
             ┌──────────────── 팀 3 「주행」 ────────────────┐
             │  터널(GPS 끊김) 통과, 속도 올리기, 전체 통합     │
             └──────────────────────┬───────────────────────┘
                                    ▼
      ┌────────── 공용 바닥 (이미 완성, 팀 3이 관리) ──────────┐
      │  브리지(UDP↔ROS2) · 로컬라이제이션 · 경로 · 제어 · FSM 코어 │
```

**각 팀은 자기 인지 노드 하나 + 자기 FSM 상태 파일만 만든다.** 서로의 코드를 볼 필요가 없다. 팀 사이 약속은 **메시지 2개**(§2)뿐이다.

# 1. 공용 바닥 — 이미 있는 것 (모든 팀이 알아야 할 것)

## 쉽게 말하면
차가 "지금 어디 있고, 얼마나 빠르고, 경로상 몇 m 지점인지"를 계속 알려주고, "얼마로 가라, 어디서 멈춰라"고 하면 그대로 해주는 기계. 여러분은 이 기계에 **"멈춰라/피해라"만 말하면** 된다.

## 구성
| 노드 | 하는 일 | 내보내는 토픽 |
|---|---|---|
| `sensor_bridge` | 시뮬 UDP ↔ ROS2 변환. 제어 패킷 송신 | `/sensors/gps` `/sensors/imu` `/vehicle/status` |
| `localization` | GPS+IMU → 맵 좌표 (x, y, yaw) | `/localization/odometry` |
| `behavior` (팀3이 새로 분리) | FSM. 이벤트 받아서 상태 정하고 목표를 냄 | `/behavior/target` `/behavior/state` |
| `tracker` (지금 `path_follower`) | 경로 따라 조향·페달 | `/control/request` |

## 좌표·단위 규약 (틀리면 합칠 때 터짐)
- **맵 좌표**: ENU, 단위 m. `map_x = UTM_x − 302595`, `map_y = UTM_y − 4124145`. 기준점 = **후륜축 중앙**.
- **yaw**: 동쪽 0, **반시계 +**, 라디안.
- **s (경로 진행거리)**: 출발점 0 ~ 2184.6 m. **모든 미션 위치는 s로 말한다.** (신호등 s=208 같은 식)
- **속도**: m/s. **조향**: 라디안, **좌회전 +**. (정규화 −1~1 변환은 브리지 한 곳에서만. 상위 모듈은 절대 안 함)
- **차량 기준 좌표(base_link)**: x 전방, y 좌측, z 상방. 원점 후륜축 중앙.
- 시간: 모든 메시지 `header.stamp`는 노드 로컬 시각. 0.5초 이상 오래된 건 버려짐.

## 미션 위치표 (s 기준, `PROJECT_MASTER.md` §5)
| s (m) | 뭐가 있나 | 팀 |
|---|---|---|
| 0 | 출발. 60초 내 109 m 통과 못하면 실패 | 3 |
| 208 / 315 / 436 / 550 / 610 | 신호 교차로 5곳 | 1 |
| 329 | 정적 장애물 (2×3×2 m). 315 신호와 14 m 차이 | 2 |
| 460 | 보행자 횡단 (10 km/h, 감지 15 m) | 2 |
| 890 | 회전교차로 NPC 끼어들기 | 2 |
| 1119 ~ 1878 | 고속 예외구간 (60 초과 허용) | 3 |
| 1881 ~ 1998 | 터널 118 m, GPS 끊김 | 3 |

## 패널티 (판단 우선순위의 근거)
**차선접촉 (3초당 5초) < 충돌 (15초) < 경로이탈 (15초 + 재주행 ≈ 24초)**
→ 피할 때 실선 잠깐 밟는 건 OK, 3초 넘기지 말 것, 경로 이탈은 절대 금지.

# 2. ★ 인터페이스 규약 — 팀 사이의 유일한 약속

## 쉽게 말하면
인지 노드는 **"봤다"** 만 말하고(`Event`), FSM은 **"그래서 이렇게 가라"** 만 말한다(`DrivingTarget`). 이 두 메시지 형식은 **팀 3 허락 없이 못 바꾼다.**

## 2-1. `foscar_interfaces/msg/Event.msg` — 인지 → FSM

```
std_msgs/Header header        # frame_id = "base_link" 또는 "map"
string  type                  # 아래 표 중 하나
float64 s                     # 이벤트가 경로상 어디에 해당하는지 (모르면 -1)
float64 x                     # 대상 위치 (frame_id 기준). 없으면 0
float64 y
float64 size_x                # 대상 크기 [m]. 없으면 0
float64 size_y
float64 vx                    # 대상 속도 (map 기준) [m/s]. 정지물이면 0
float64 vy
string  value                 # 부가 정보. 신호색 "RED"/"YELLOW"/"GREEN"/"LEFT" 등
float64 confidence            # 0~1
```

| type | 내는 팀 | value | 비고 |
|---|---|---|---|
| `TRAFFIC_LIGHT` | 1 | `RED` `YELLOW` `GREEN` `LEFT` `UNKNOWN` | 3프레임 안정화 **후** 발행 |
| `OBSTACLE` | 2 | — | 정지물. x,y,size는 base_link |
| `PEDESTRIAN` | 2 | — | 움직임 있음. vx,vy 채움 |
| `VEHICLE` | 2 | — | NPC. 회전교차로용 |
| `GPS_LOST` / `GPS_OK` | 3 | — | 로컬라이제이션이 발행 |

**규칙**
- 토픽 `/events`, 큐 10. **본 것만 낸다. 판단은 안 한다.** ("장애물이 있으니 멈춰라"가 아니라 "여기 이런 크기의 정지물이 있다")
- 같은 대상은 계속 재발행(10 Hz 이상). FSM은 마지막 발행 후 0.5초 지나면 없어진 것으로 본다.
- 깜빡이는 오탐을 걸러서 낼 책임은 **인지 쪽**에 있다 (N프레임 확인 → §5 공통 패턴).

## 2-2. `foscar_interfaces/msg/DrivingTarget.msg` — FSM → 제어

```
std_msgs/Header header
string  state                 # 현재 FSM 상태 이름 (로깅용)
float64 v_max                 # 이 이상 내지 마라 [m/s]. 정지 = 0
float64 stop_s                # 여기서 정확히 서라 (경로 진행거리 m). 없으면 NaN
float64 lat_offset            # 경로에서 옆으로 이만큼 비켜 가라 [m]. 좌 +. 기본 0
```

**규칙**
- 토픽 `/behavior/target`, 20 Hz. 제어기는 **이것 말고 아무것도 안 본다.**
- `stop_s`가 있으면 제어기가 앞바퀴 기준으로 그 s에 정지하도록 감속 프로파일을 만든다. (앞바퀴 = 후륜축 + 3.0 m)
- `lat_offset`은 제어기가 0.5 m/s² 이내로 부드럽게 반영. 급격히 바꿔도 차는 안 튄다.
- 0.5초 동안 안 오면 제어기는 **브레이크**.

## 2-3. FSM 상태 파일 규약 — 각 팀이 만드는 것

`foscar_planning/foscar_planning/states/<이름>.py` 에 클래스 하나:

```python
from foscar_planning.state import BehaviorState, Context, Target

class StopLine(BehaviorState):
    name = "STOP_LINE"
    priority = 50          # 클수록 우선. §2-4 표 참조

    def check_entry(self, ctx: Context) -> bool:
        # 이 상태로 들어갈 조건. ctx 에 s, x, y, yaw, v, events(최근 이벤트 목록), route 가 있음
        ...

    def check_exit(self, ctx: Context) -> bool:
        # 이 상태에서 나갈 조건
        ...

    def compute_target(self, ctx: Context) -> Target:
        # 이 상태일 때 차에게 시킬 것. Target(v_max=, stop_s=, lat_offset=)
        ...
```

- FSM 코어는 매 틱 `priority` 높은 순으로 `check_entry`를 보고, 하나만 활성화한다. 활성 상태의 `check_exit`가 참이 되면 `CRUISE`로 돌아간다.
- **각 팀은 자기 상태 파일만 만든다.** 코어(`state.py`, `behavior_node.py`)는 팀 3 소유.
- 상태 안에서 시간 재기 (예: "3초 서 있었으면") 는 `ctx.now` 사용. `time.time()` 금지 (재생 테스트 안 됨).

## 2-4. 우선순위표 (충돌 시 누가 이기나)

패널티 서열 = 우선순위. 두 상태가 동시에 들어가려 하면 큰 숫자가 이긴다.

| priority | 상태 | 팀 | 근거 |
|---|---|---|---|
| 100 | `EMERGENCY` | 3 | 센서 끊김·경로이탈 → 즉시 정지 |
| 80 | `YIELD` (보행자·NPC 앞 정지) | 2 | 충돌 15초 |
| 70 | `AVOID` (정적 장애물 회피) | 2 | 충돌 15초 |
| 60 | `STOP_LINE` (신호 정지) | 1 | 위반 15초 |
| 40 | `TUNNEL` | 3 | 감속·추측항법 |
| 0 | `CRUISE` | 3 | 기본 |

**주의**: s=315 신호와 s=329 장애물이 14 m 차이. `STOP_LINE`(빨강)과 `AVOID`가 겹치면 AVOID(70)가 이기지만, AVOID의 `compute_target`는 **stop_s가 있으면 유지해야 한다.** → 코어가 "낮은 우선순위 상태의 `stop_s` 중 가장 가까운 것"을 자동으로 합쳐 준다 (팀 3 구현). 팀 2는 신경 안 써도 됨.

# 3. 팀 1 「신호」 — 카메라

## 쉽게 말하면
**교차로 5곳에서 신호등 색을 보고, 빨간불이면 정지선 앞에 서고, 초록불이면 그냥 지나간다.** 위반하면 한 번에 15초. 신호 정답값을 주는 채널은 금지라 **카메라로만** 봐야 한다.

## 만드는 것 2개
1. **`foscar_camera/traffic_light_node.py`** — 영상 → 신호색 → `Event(type=TRAFFIC_LIGHT, value=색)`
2. **`foscar_planning/states/stop_line.py`** — 정지선 앞에서 서고 초록 되면 출발

## 세부

### 3-1. 신호 인식 노드
- 입력 `/sensors/camera/front/compressed` (1280×720, FOV 90°, 20 Hz). 필요하면 좌/우도.
- 출력 `/events` `TRAFFIC_LIGHT`, `s` = 다음 정지선 s (§1 표에서 현재 s보다 큰 첫 번째), `value` = 색.
- **3프레임 안정화**: 같은 색 3번 연속일 때만 발행. 작년 `controller.cpp:83-97` 그대로.
- 방법 후보: ① 작년 YOLO(`1027_40epoch.pt`) — 올해 K-City에서 되는지 **현장점검 캡처로 먼저 확인** ② HSV 색 검출 + ROI (신호등은 화면 위쪽) ③ 둘 다.
- **날씨·시간 랜덤** (Sunny/Foggy × 11/13/15시). 셋 다에서 되는지 확인 필수. 이게 제일 어려운 부분.
- 성능: CPU에서 20 Hz 못 내면 10 Hz로 낮춰도 됨 (신호는 10 Hz면 충분).
- 자유 카메라 1대를 **망원(FOV 30°)** 으로 붙여 멀리서 미리 보는 방안 검토. 붙이면 `sensor_bridge` 설정에 추가 (팀 3에 요청).

### 3-2. STOP_LINE 상태
```
진입: 다음 정지선까지 40 m 이내 AND 최근 TRAFFIC_LIGHT 이벤트가 RED 또는 YELLOW
       (이벤트 없으면 = UNKNOWN → 안전하게 진입, 정지선 앞 감속)
목표: stop_s = 정지선 s (앞바퀴 기준으로 코어가 처리), v_max = 현재 속도 유지
탈출: GREEN 3프레임 확인 OR 정지선을 이미 3 m 지남
```
- 감속 중 초록으로 바뀌면 안 서고 통과 (작년 로직).
- 정지선 s 값 5개는 `foscar_planning/config/stop_lines.yaml` 에 (링크 데이터에서 추출, 팀 3이 초기값 제공).
- 판정은 **앞바퀴가 정지선 넘는 순간**의 신호다. 노란불에서 애매하면 **선다** (15초 vs 0초).

# 4. 팀 2 「장애물」 — 라이다

## 쉽게 말하면
**라이다로 앞에 뭐가 있는지 보고, 정지물이면 옆으로 피하고, 사람·차면 멈춰서 기다린다.** 부딪히면 한 번에 15초. 주변 객체 정답값 채널은 금지라 **포인트클라우드에서 직접** 찾아야 한다. 뭐가 나올지 정해져 있지 않아서("임의 장애물") 종류 구분 없이 "덩어리"를 찾는 방식이 맞다.

## 만드는 것 3개
1. **`foscar_lidar/obstacle_node.py`** — 포인트클라우드 → 덩어리 → `Event(OBSTACLE / PEDESTRIAN / VEHICLE)`
2. **`foscar_planning/states/avoid.py`** — 경로 위 정지물 → 옆으로 비켜 감
3. **`foscar_planning/states/yield.py`** — 움직이는 것 앞에서 정지, 지나가면 출발

## 세부

### 4-1. 장애물 인식 노드
- 입력 `/sensors/lidar/points` (VLP16, 10 Hz, frame `lidar`, x 전방 / y 좌 / z 상).
- 파이프라인: **관심영역 자르기**(전방 40 m, 좌우 ±6 m, 높이 −0.3~2.5 m) → **지면 제거**(RANSAC 평면 or 높이 임계) → **클러스터링**(DBSCAN 또는 Euclidean, 거리 0.5 m, 최소 5점) → 클러스터마다 중심·크기.
- **경로 위인지 판정**: 클러스터 중심을 map 좌표로 바꿔 경로에 투영. 경로에서 횡 1.5 m 이내면 "경로 위". `Event.s` = 그 투영 s.
- **정지/이동 구분**: 같은 클러스터를 5프레임 추적해서 이동 속도 추정. 0.5 m/s 이상이면 `PEDESTRIAN`(작음) 또는 `VEHICLE`(큼), 아니면 `OBSTACLE`.
- **N프레임 확인 필터**(§5): 3프레임 연속 봐야 발행. 사라지면 1프레임씩 감점.
- 라이다 장착 위치는 **아직 미공개** → 현장점검에서 확인, `base_link → lidar` TF는 팀 3이 브리지에 넣음.

### 4-2. AVOID 상태 (정적 장애물, s=329)
```
진입: OBSTACLE 이벤트가 경로 위 AND 30 m 이내 AND 정지물
목표: lat_offset = ±(장애물 반폭 + 차 반폭 0.95 + 여유 0.5). 방향은 빈 쪽 (기본 좌)
      v_max = 4 m/s
탈출: 장애물 s 를 5 m 지남 → lat_offset 0 으로 복귀 (코어가 부드럽게)
```
- 차선폭 3.5 m, 차폭 1.9 m → 옆으로 최대 1.3 m 정도. 장애물 폭 2 m면 옆 차선을 밟아야 함 → **실선 3초 이상 밟지 않게** 빨리 지나간다 (차선접촉 5초 < 충돌 15초).
- s=315 신호와 14 m 차이: 빨간불에 서 있다가 출발하면서 바로 회피. `stop_s`는 코어가 합쳐주므로 AVOID는 `lat_offset`만 신경 쓰면 됨.

### 4-3. YIELD 상태 (보행자 s=460, 회전교차로 s=890)
```
진입: PEDESTRIAN 또는 VEHICLE 이벤트가 앞으로 20 m 이내 AND 경로와 교차할 것 같음
       (대상 위치 + 속도×2초 가 경로 1.5 m 이내)
목표: stop_s = 대상 s − 5 m, v_max = 0 근처
탈출: 대상이 경로에서 벗어남 (2초 연속 교차 안 함) OR 데드락 타이머 만료
```
- **데드락 타이머**: 회전교차로에서 NPC가 5초 주기로 계속 오면 영원히 못 들어감. 정지 후 **8초** 지나면 다음 gap에 진입. 작년 `controller.cpp:257-345` 참고.
- 보행자는 10 km/h로 횡단. 감지거리 15 m 규정이니 20 m 앞에서 보고 정지하면 여유 있음.

## 6-2. N프레임 확인 패턴 (인지 팀 공통)

```
같은 대상(비슷한 위치·크기)이 보이면 count += 1, 안 보이면 count −= 1 (0 이하 삭제)
count ≥ N (신호 3, 장애물 3) 일 때만 Event 발행
15프레임 안 보이면 캐시에서 삭제
```
