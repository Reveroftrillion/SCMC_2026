# ctrl_lidar — 라이다 장애물 인지 (팀 2)

> 작성 2026-09-16. VLP-16 포인트클라우드에서 장애물을 찾아 `/events` 로 내보내는 패키지.
> 규약 원문은 `개발계획서.md` §4, 베이스 코드 연결 지점은 `BasecodeGuideline/베이스코드가이드.md`.

## 터널 반사 강도 필터

`/behavior/mission`의 현재 미션이 `TUNNEL`이면 **intensity가 정확히 0인 점을 전부 장애물 군집화에서 제외**합니다. 높이·형상 조건은 없습니다.
다른 미션에서는 적용하지 않으며, 미션 메시지가 1초 이상 끊기거나 intensity 필드가 없으면 제외하지 않습니다.
원본 `/sensors/lidar/points`와 빈 공간 확인용 원본 점은 유지합니다. RViz 원본 점군에는 벽이 계속 보일 수 있습니다.
2026-09-25 터널 정차 기록 100스캔 재처리에서 매 스캔 상자 1개가 유지됐습니다. 회피 조향 중 실주행은 별도 확인이 필요합니다.

# ⚡ 실행 방법 (먼저 읽으세요)

```bash
cd ~/2026Morai/2026foscar
source install/setup.bash
ros2 launch ctrl_lidar ctrl_drive.launch.py
```

**이 한 줄이면 자율주행(상한 100 km/h) + 라이다 인지 + 카메라 3대 + 신호등 인식 + 뷰어 창 4개가 전부 뜹니다.**
주행 스택(`ctrl_bringup`)·라이다·카메라(`ctrl_camera`)를 따로 띄울 필요 없습니다.
카메라 그룹은 주행 스택이 자리 잡도록 **5초 뒤에** 뜹니다 (동시에 띄우면 `control loop stalled` — 2026-09-19 부터 FAULT 가 아니라 그 틱만 HOLD 지만, 여전히 피하는 게 좋습니다).

## 🚨 2026-09-16 부터 기본값이 바뀌었습니다

| | 이전 | **지금** |
|---|---|---|
| `drive` | `false` (차 안 움직임) | **`true` (띄우면 바로 출발)** |

**띄우는 순간 차가 출발합니다.** 예전 습관대로 `drive:=true` 를 붙이실 필요 없고,
반대로 **차를 세워두거나 직접 몰려면 반드시 `drive:=false` 를 붙이세요.**

```bash
ros2 launch ctrl_lidar ctrl_drive.launch.py drive:=false    # 직접 몰 때 / 인지만 볼 때
```

> `drive:=false` 를 안 붙이고 수동 조작하면 베이스와 서로 핸들을 뺏으려고 싸웁니다.
> 게다가 제어 명령이 없는 동안 `ctrl_bridge.py` 가 기본값으로 **풀 브레이크를 50 Hz 로 계속 보내서**
> 차가 아예 안 움직입니다. "수동으로 몰려는데 차가 꿈쩍도 안 한다" 면 십중팔구 이것입니다.

## 뷰어 창 보는 법

**위** = 위에서 본 모습(오른쪽이 전방, 노란 점선 = ROI) · **아래** = 옆에서 본 모습
(갈색 지면선 위에 점이 깔리면 장착 높이가 맞는 것) · **오른쪽** = 수신 주기 / 포인트 수 /
장착 높이 실측 비교 / `/events` 목록.

오른쪽 패널 둘째 줄이 제일 중요합니다:

```
자차 : 20.0 km/h   ego 보상 ON        ← 정상
자차 : odom 없음 → 상대속도 모드        ← Ego 상태(9099) 미연결. 분류 결과 믿지 마세요
```

## 3. 확정된 값과 근거

### 3-1. 라이다 장착 위치 `x=2.00  y=0.00  z=2.11`

**MORAI 센서 패널에는 `z=1.75` 로 나오지만 그건 차량 원점 기준이고, 차량 원점이
지면에서 0.36 m 위에 있습니다.** 우리가 필요한 건 지면 기준 높이라 **2.11** 이 맞습니다.

- 전방 8~30 m 노면에 평면을 맞춰 실측: 구간별 −2.10 ~ −2.12 m, 잔차 0.135 m
- 카메라 영상에 라이다 점을 투영했더니 지면 점이 실제 노면 위에 정확히 얹힘 (독립 검증)

`1.75` 로 두면 지면이 ROI 아래 경계 밖으로 밀려나면서 **장애물 아래쪽 0.36 m 가 같이 잘려
ROI 안 포인트가 1889 → 175 개로 줄어듭니다.** 현장에서 값이 다르면 `lidar_z:=` 로 넘기면
되고, 뷰어가 실행 중에 실측값과 비교해서 틀리면 경고를 띄웁니다.

### 3-2. 좌표 규약

```
x = R·cos(방위각)     y = −R·sin(방위각)     z = 거리·sin(수직각)
→ 방위각 0도 = 차량 전방, +y = 좌측, +z = 상방 (ROS REP-103)
```

K-City 정차 상태에서 지면 위 구조물 988개 중 **910개가 +x 쪽**에 몰리는 것으로 확정했습니다
(신호등·기둥이 전부 차 앞에 있는 장면과 일치). 작년 팀이 표준 `velodyne_pointcloud` 를
쓴 것과도 맞습니다.

### 3-3. MORAI 포트 — **Competition 채널만 씁니다**

대회 규정상 **Ego 계열 채널은 금지, Competition 계열만 허용**입니다. MORAI 네트워크 탭의
메시지 타입 드롭다운에서 반드시 **Competition** 이 붙은 항목을 고르세요.

| 포트 (노트북 수신) | 메시지 타입 | 비고 |
|---|---|---|
| 9302 | VLP-16 (1206 byte, `0xFFEE`, factory `0x37 0x22`) | 센서 탭. 이 패키지가 사용 |
| 9099 | **Competition Vehicle Status** `#MoraiInfo$` **181 byte** | **Ego Vehicle Status(229 byte)가 아님.** `sensor_bridge` 가 181 byte 만 받음 |
| 9093 (시뮬 수신) | Ego Ctrl Cmd `#MoraiCtrlCmd$` 23 byte | 제어 송신. 금지 목록에 없음 |
| 9102 / 9104 | GPS / IMU | 센서 탭 |
| 9208 | 카메라 7번 (1280×720, 신호 인식) | 센서 탭. 다른 카메라는 쓰지 않는다 (2026-09-29) |
| 9092 | `#CollisionData$` | 충돌 감지, 채점 확인용 |

**금지 채널 — 연결하지 말 것** (개발계획서 §6 규칙: 포트 번호를 주석·설정에도 적지 않는다)
- Object Info (주변 객체 정답값)
- Ego Vehicle Status (229 byte 짜리)
- TrafficLight Status (신호등 정답값)

이 패키지는 셋 다 쓰지 않습니다. 라이다 포인트클라우드만 씁니다.

> 상태(9099)가 안 오면 `localization` 이 침묵 → odom 없음 → **ego 보상이 꺼져서
> 정지 장애물이 전부 이동물로 오분류**됩니다. `sensor_bridge` 로그의
> `RX={'status': 0}` 이 그 증상입니다. **상태가 오긴 오는데 `parse_errors` 가 올라가면
> Ego Vehicle Status(229 byte)를 골랐을 가능성이 큽니다 — Competition 으로 바꾸세요.**

## 4. 파이프라인

### 4-1. 좌표 변환
장착 오프셋(또는 `base_link→lidar` TF)을 더해 **base_link 기준(지면 z=0)** 으로 먼저 옮깁니다.
그래야 ROI·지면 임계값을 "지면 = 0" 이라는 직관적인 값으로 다룰 수 있습니다.

### 4-2. ROI + 지면 제거 (불리언 마스크 한 번, 파이썬 루프 없음)
```
전방 0~40 m, 좌우 ±6 m, 높이 −0.3~2.5 m
지면 임계값 = 0.15 + 0.01 × 거리      (40 m 에서 0.55 m)
```
**지면 임계값이 거리에 비례하는 이유**: `−3도` 빔이 40 m 지점에서 노면을 거의 수평으로
스칩니다. 노면이 몇 cm만 울퉁불퉁해도 점이 크게 튀어서 실측상 30~40 m 구간 점의 **50%가
0.15~0.50 m 높이대**에 몰렸습니다. 가감속 시 차가 1도만 끄덕여도 40 m 에서 지면이 0.7 m
어긋나는 것도 같이 흡수합니다.

### 4-3. 클러스터링 — **2D(x,y) 투영**, 3D 아님

VLP-16 은 빔 간격이 2도라 거리가 멀수록 링이 수직으로 벌어집니다. 보행자 크기(0.5×1.7 m)
물체를 거리별로 스캔해 비교한 결과:

| 거리 | 링 간격 | 2D (현재) | 3D eps=0.5 |
|---|---|---|---|
| 10 m | 0.35 m | 1개 | 1개 |
| 15 m | 0.52 m | 1개 | **3조각** |
| 20 m | 0.70 m | 1개 | **2조각** |
| 30 m | 1.05 m | 1개 | **2조각** |

**15 m 부터 링 간격이 eps(0.5)를 넘어 3D 는 한 물체를 링마다 쪼갭니다.** 쪼개지면 크기가
엉터리가 되고, 조각당 점 수가 `min_samples` 에 못 미치면 통째로 놓칩니다.

**3D 정보를 버리는 게 아닙니다** — 거리 계산만 2D 로 하고, 높이(`z_max`, `size_z`)는 그대로
계산해서 노면 잔재 제거·보행자 판정에 씁니다.

### 4-4. 추적과 속도
- 관측을 **map 좌표로 올려서** 추적합니다. base_link 로 쌓으면 자차가 움직일 때 정지물도
  움직이는 것으로 보입니다 (30 km/h 면 전봇대가 8.3 m/s 로 다가옴).
- 최근 5프레임 위치에 **최소자승 직선**을 맞춰 기울기를 속도로 씁니다 (차분보다 노이즈에 강함).
- odom 이 0.5초 이상 끊기면 상대속도 모드로 강등하고 경고합니다. (2026-09-19 부터 `localization` 은 GPS 가 없어도
  추측항법으로 odom 을 계속 내므로, 터널에서도 ego 보상은 유지됩니다. odom 이 끊기는 건 IMU/status 가 1.5 s 넘게 안 올 때뿐.)

### 4-5. 분류 — 크기·높이·속도가 앞뒤 맞아야 도로 이용자
```
1. 이동 판정 (히스테리시스)  들어갈 때 0.8 m/s, 나올 때 0.4 m/s + 궤적 직진성 0.6 이상
2. 20 m 이내에서 높이 0.6 m 미만          → OBSTACLE (라바콘·연석)
3. 두께 0.25 m 미만                       → OBSTACLE (벽·가드레일 조각)
4. 가로세로비 4.0 초과                    → OBSTACLE (차는 4.5×1.9 = 2.4 라 안 걸림)
5. 크기 ≤ 1.2 m  →  속도 ≤ 3.0 m/s 면 PEDESTRIAN, 아니면 OBSTACLE
6. 크기 ≥ 2.0 m  →  VEHICLE
7. 1.2~2.0 m 애매한 구간                  → OBSTACLE (단정하지 않음)
```

각 조건이 왜 있는지는 §6 의 실측 기록을 보세요. 전부 **실제로 발생한 오분류를 막기 위해**
하나씩 추가된 것이고, 시뮬 회귀 테스트로 진짜 보행자·차량은 계속 잡히는 걸 확인했습니다.

### 4-6. N프레임 안정화
**3프레임 연속** 탐지되어야 발행하고, 놓치면 점수를 1씩 깎아 **15프레임** 째에 삭제합니다.
한 번 놓쳤다 돌아오면 바로 재발행되므로 깜빡이지 않습니다.

### 4-6.5. **"내가 갈 길을 막고 있는가" — 종류를 가리지 않는 기하 판정** (2026-09-20)

가드레일 오탐의 뿌리는 판정 기준이 **분류 결과에 따라 달랐다**는 점입니다 (정지물 2 m / 이동물 5 m).
가드레일이 `VEHICLE` 로 한 번 오분류되면 임계가 완화돼 필터까지 같이 뚫렸습니다.

지금은 **분류와 무관한 질문 하나**만 던집니다. 보행자인지 차량인지 가리지 않습니다 —
도로 안에 뛰어든 무언가면 그 자체로 장애물이고, 멈출지 비켜갈지는 그 뒤 FSM 이 정합니다.

```
1) 지도상 도로 안인가        (link_set.json 링크 합집합, 여유 road_margin_m = 0)
2) 도로를 가로지르는 폭이     (경로 좌표 d 범위 ≤ max_block_width_m = 2.0 m)
   차 한 대보다 좁은가
3) 내 통로를 막고 있는가      (가장 가까운 모서리가 corridor_half_m = 1.5 m 안)
```

**1) 도로 마스크** — `link_set.json`(634 링크 · 중심선 + 폭 3.5 m)을 0.25 m 로 리샘플한 149k 점 KD-트리.
`도로 밖 거리 = 가장 가까운 링크 중심선까지 거리 − 그 링크 반폭`. 모든 링크의 **합집합**이 도로라
옆 차로·반대 차로·교차로 내부가 포함됩니다 ("내 길 위인가" 는 3 번이 따로 판단).
도로에서 `road_point_margin_m`(2.5 m) 넘게 벗어난 점은 **클러스터링 전에** 버려서, 가드레일 조각이
진짜 물체와 한 덩어리로 묶이는 것도 막습니다.

**2) 경로 가로폭** — 모양은 반드시 **경로 좌표(Frenet)로** 재야 합니다. 바운딩박스 네 모서리를 경로에
투영해 s·d 범위를 구합니다. 차량 좌표(`size_x`/`size_y`)로 "얇고 길면 버림" 을 했더니 **회피 박스의
40% 가 같이 죽었습니다** — 27 m 밖 박스는 앞면만 보여 0.3×1.4 라 레일 조각과 똑같이 생겼기 때문입니다.
경로 좌표로 재면 **박스 d폭 1.47 m vs 레일 조각 3.48 m** 로 명확히 갈립니다.

**3) 통로** — 중심이 아니라 **가장 가까운 모서리** 기준입니다. 차 한 대가 차선을 반쯤 물고 서 있으면
중심은 통로 밖이어도 막고 있는 것입니다. 움직이는 물체는 `path_predict_s`(2 s) 뒤 예상 위치로도
보되, **그 예상 위치도 도로 안** 이어야 합니다.

**실측 검증** (2026-09-20, 장애물이 하나도 스폰되지 않은 시나리오 = 발행된 것이 전부 오탐):

| 주행 | 이전 기준 | 새 기준 |
|---|---|---|
| 오탐만 있는 주행 | `OBSTACLE` 170 · `PEDESTRIAN` 11 · `VEHICLE` 8 | **1건** (32 m 단발) |
| 박스 + 보행자 주행 | — | 이벤트 60건 **전부 실제 물체**, 오탐 0 |

### 4-7. 경로 투영 — `Event.s` 채우기
`/map/route` + `/localization/s` 로 덩어리를 전역경로에 투영해 `Event.s` 를 채웁니다.
발행 여부 판단은 4-6.5 가 합니다.

`|y|`(직진축 기준 좌우거리)로 거르면 **곡선에서 틀립니다.** 도로가 휘면 바깥쪽 가드레일이
직진축 기준으로는 안쪽(`y +1.6`)에 들어옵니다 — 실제로 카메라로 확인했습니다. 그래서 거리 판정은
전부 경로 투영(Frenet) 기준입니다.

**자차가 경로에서 10 m 넘게 벗어나면 경로·도로 필터가 자동으로 꺼집니다.** 코스를 이탈했는데
인지까지 먹통이 되면 안 되기 때문입니다 (경고 로그 + `s = -1` 로 전부 발행).

## 7. 알려진 한계

**1. 라이다가 8 Hz 입니다 (10 Hz 아님)**
```
평균 8.2~8.4 Hz, 최소 3.4 Hz, 최대 11.7 Hz
```
끊기지는 않는데 주기가 들쭉날쭉합니다. **우리 처리 시간은 5~11 ms 라 우리 탓이 아니고
시뮬 출력 자체가 그렇습니다** (측정 당시 시뮬 FPS 23). 3.4 Hz 구간에선 0.29초 동안 못 보는
셈이라 58 km/h 면 4.7 m 를 눈감고 갑니다. 규정 감지거리 15 m 엔 여유가 있지만
**완료 기준의 "10 Hz 유지" 는 미달**입니다. 시뮬 Quality 를 낮추면 나아질 수 있습니다.

**2. 근거리 낮은 물체는 안 보입니다**
VLP-16 의 가장 아래 빔이 −15도라, 높이 2.11 m 기준 **가장 가까운 지면 반사가 7.9 m 앞**입니다.
차 바로 앞 3 m 이내의 낮은 물체(라바콘 등)는 빔 아래로 빠집니다. 센서 특성이라 어쩔 수 없고,
AVOID 진입 판단을 30 m 밖에서 하는 이유이기도 합니다.

**3. 먼 거리에서는 높이를 못 믿습니다**
30 m 에서 빔 간격이 1.05 m 라 물체 높이를 제대로 못 잽니다. 그래서 높이 검사(§4-5 2번)를
20 m 이내에만 적용합니다 — 멀리 있는 진짜 보행자를 놓치지 않기 위해서입니다.

**4. 길가 구조물이 여전히 많습니다**
경로 필터 적용 전 기준으로 전체 이벤트의 **96.5% 가 경로에서 3.5 m 이상 떨어진 길가
구조물**이었습니다. §4-7 경로 필터가 이걸 잡으라고 있는 건데, 실주행에서 줄어든 양은
아직 측정 못 했습니다 (측정 시점에 차가 경로를 51 m 벗어나 있었음).

### 2026-09-22: 넓은 관측과 주행 장애물의 분리

좌우 ROI 기본값은 ±20m로 유지한다. `/events`와 기존 RViz 장애물 표시는
`on_route_path`의 도로/경로 기하 판정을 통과한 관측만 받는다. 인접 도로의 차량 및
이미 통과한 도로 이용자는 `/perception/road_users`로 별도 발행한다. 이 토픽은
관측 전용이며 정적 회피나 양보 상태에 새로 진입시키지 않는다. 새 차량 예측과
이미 기다리던 같은 ID의 통과 확인에만 사용한다.

통과 확인은 현재 관측이 경로 필터를 벗어났다는 증거가 새 프레임에서0.35초
이어질 때 해제할 수 있다. 캐시를 반복해서 읽거나 다른 물체를 보는 것은 통과
확인이 아니다. 두 토픽은 같은 라이다ID와 센서 시각으로 순서를 맞춘다.

기존 departure_observation의 도로 필터 우회를 제거했다. 지도 속도 벡터를
base_link 변위로 회전한 뒤 미래 바운딩박스를 경로에 투영한다. 구조물로 새롭게
확인된 트랙은 과거 VEHICLE/PEDESTRIAN 라벨만으로 동적 분류를 유지하지 않는다.

지도는 링크 중심선과 폭의 합집합이고 물체 외곽은 관측 바운딩박스다. 지도 오차나
가림까지 포함해 모든 구조물의 실제 외곽을 보증하는 방식은 아니다. 실제 주행
통로를 침범한 구조물은 장애물로 남겨야 한다. 관련 검증은
회전교차로의 현재 사용 방식은 [최신 개발 상태](../../ROUNDABOUT.md)를 참조합니다.

### 부분 관측된 동적 대상

`DYNAMIC_UNKNOWN`은 사람/차량 종류는 미확정이지만 여러 관측에서 map 기준
이동이 확인된 대상이다. 1.2–2m 부분 차량처럼 크기만으로 종류를 정할 수
없어도 정적장애물로 바꾸지 않는다. 현재 기준은 3개 이상 관측, 0.19초 이상,
0.6m 이상 이동, 모든 관측 간 전진 속도0.8m/s 이상, 경로 직진성0.95 이상이다.
관측 간격0.25초 초과 또는 odometry가 없으면 이 판정을 새로 확정하지 않는다.
기존 도로·구조물·높이·폭 필터를 통과해야 하며 순간 중심점 점프만으로
정적 상자를 동적으로 바꾸지 않는다. 이미 확정된 대상은 정지하더라도
미확정 동적 상태를 유지하고, 더 큰 차체가 보이면 VEHICLE로 갱신할 수 있다.

동적 미확정 이벤트는 양보·예측에서 다루고 정적 회피 대상에서는 제외한다.
예측 차체는 보수적으로 차량 최소 크기를 적용한다. RViz 표시는 보라색이다.
Event 메시지의 기존 string type을 사용하므로 필드/직렬화 변경은 없다.


회전교차로 접근 관측은 `roundabout_observation_begin_s=860.0`부터
`roundabout_observation_end_s=920.0`까지 `roundabout_roi_y_abs=30.0`을 사용한다.
기본 좌우20m 밖의 추가 점은 유효한 지도/자차 위치가 있고 도로 안(`road_margin`)일 때만 허용한다.
다른 구간이나 지도/위치 누락 시 기존 ROI를 유지한다. 추가 관측 자체는 양보·정지 명령이 아니다.
