# 1. `ctrl_recorder_node.py` — 수집

```python
class RecorderNode(Node):
    """RGB + semantic 을 MORAI 타임스탬프로 짝지어 저장. 판단은 최소로."""

    def __init__(self)
        # 파라미터 → message_filters Subscriber 2개 + s 1개
        # → ApproximateTimeSynchronizer(queue_size, slop_s) → 출력 디렉토리
        # check=True 면 출력 디렉토리를 아예 안 만든다 (진단은 아무것도 남기지 않는다)

    def _count_rgb(self, msg) -> None            # 짝 성공률을 보려면 스트림별 장수도 필요하다
    def _count_sem(self, msg) -> None

    def on_s(self, msg: Float64) -> None
        """현재 s 보관. localization 이 없으면 계속 None → 시간 기준으로만 저장."""

    def on_pair(self, rgb: CompressedImage, sem: CompressedImage) -> None
        """message_filters 콜백. 짝이 맞은 한 쌍이 들어온다."""
        # dt_ms = |rgb.stamp - sem.stamp|  (진단용, meta 에 기록)
        # check 모드면 diagnose() 로 빠짐
        # should_save() 가 True 면 save()

    def should_save(self) -> tuple[bool, str]
        """(저장할까, 이유). 이유는 meta 의 reason 열."""
        # moved: |s - last_saved_s| >= step_m
        # timed: now - last_saved_t >= interval_s     ← 정차·저속 구간을 덮는다
        # 첫 프레임은 무조건 저장. s 가 없으면 timed 만으로 동작

    def save(self, rgb: bytes, sem: bytes, stamp, dt_ms: float, reason: str) -> None
        """받은 JPEG 를 그대로 쓴다 — 재압축하지 않는다. meta.csv 에 한 줄 추가하고 flush.
        (런치를 Ctrl-C 로 끊어도 거기까지는 남는다.)"""

    def report(self) -> None
        """3 초 주기 로그 (ctrl_camera 관례). 스트림별 Hz, 짝 Hz 와 성공률,
        dt 평균·최대, s, 저장 수. 짝이 0 이면 무엇을 확인할지 찍는다."""

    # --- check 모드 ---
    def diagnose(self, rgb_msg, sem_msg, dt_ms) -> None
        """팔레트·JPEG 손상·해상도 확인 + extract.label_frame 으로 박스를 뽑아 통계."""
    def collect_boxes(self, boxes, height) -> None
        """3구/4구/보행자/병합 개수, 종횡비, 세로 위치, 잘린 박스 수를 누적."""
    def show_overlay(self, rgb, sem, boxes, dt_ms) -> None
    def check_summary(self) -> None              # 두 번 불려도 한 번만 찍는다
    def destroy_node(self)                       # check 면 요약, 아니면 meta 닫기

def label_of(kind, n_aspect) -> str              # ('vehicle', 4) → '4구'
def stamp_ns(stamp) -> int
def decode(msg: CompressedImage)
def main(args=None)
```

## 1-3. `check` 모드 — 본 수집 전 반드시 먼저

저장하지 않고 [개발명세서.md §7](개발명세서.md) 의 가정을 한 번에 검증한다.

```
1. 두 스트림 Hz, 짝 성공률                    report() 가 3 초마다
2. |Δstamp| 분포 (중앙/p95/최대)               → 같은 시뮬 프레임인가
3. semantic 색 상위 10색 (픽셀 %)              → 팔레트 확정
   TL_COLOR 언저리의 **정확한 최빈색**         → 값이 빗나갔으면 바꿀 값을 그대로 알려준다
   TL_COLOR 근처 픽셀 % 와 그중 중간색 %       → JPEG 손상 지표
4. 해상도 불일치 경고                          → 두 카메라가 같은 FOV·해상도인가
5. 박스 통계                                   → 3구/4구/보행자/병합 개수, 검수행 사유
   박스별 w×h, 종횡비 r, margin, 판정, 클래스  → 종횡비 임계를 이 값으로 고친다
   세로 위치와 잘린 박스 수, ROI 후보          → ROI 와 카메라 pitch 를 이 값으로 정한다
6. 오버레이 창                                 → 박스를 RGB 위에. 글자는 `77x19 r4.05 4구 red`
      초록=확실  노랑=검수행  회색=램프 꺼짐
      s 키 = 한 쌍 저장 (~/foscar_logs/check)   q 키 = 종료
```

박스는 `extract.label_frame` 으로 뽑는다 — **라벨링과 같은 코드 경로다.** 진단이 따로
구현하면 "check 에선 4구였는데 extract 에선 3구" 같은 어긋남이 생기고 알아챌 방법이 없다.
`min_box_px` 도 `ctrl_extract.py` 와 같은 값을 써야 한다 (`record.yaml`).

실제로 2026-09-22 에 이 진단이 없어서 팔레트를 손으로 재야 했다. 지금은 틀린 값으로 돌리면
`→ ⚠ 최빈색이 TL_COLOR 에서 75.7 떨어져 있습니다. ctrl_palette.py 의 TL_COLOR 를 (239, 74, 255)
로 바꾸세요.` 가 바로 나온다.

# 6. ✅ `ctrl_camera_bridge.py` — `stamp_source` (적용 완료)

`ctrl_camera` 는 대회 패키지다. **여기 들어간 변경은 이것 하나뿐이고 `semantic` 이라는 단어도 안 들어간다.** 기본값이 기존 동작이라 주행 파이프라인은 무변경.

## 왜 필요했나
MORAI 헤더에 `sec`/`nsec` 가 있는데 offset 15 의 `size` 만 읽고 버렸다. 수신 시각으로 짝을 맞추면 조각 유실 시 **한 프레임씩 밀려 짝지어질** 수 있고, 50 ms 밀리면 20 m 거리에서 **9 px** 오차다. 그 라벨은 조용히 틀린다. 근거는 [개발명세서.md §3-7](개발명세서.md).

```
'MOR'  sec   nsec  index  size   JPEG
0-2    3-6   7-10  11-14  15-18  19-
        └─ 이제 읽는다    └─ 원래 읽던 것
```

## 실제로 바뀐 곳

```python
# ① __init__  — 파라미터
self.stamp_source = str(p('stamp_source', 'recv').value)   # recv | morai
if self.stamp_source not in ('recv', 'morai'):
    raise ValueError(...)                                  # 오타로 조용히 recv 가 되는 것을 막는다

# ② receive()  — 첫 조각에서 스탬프 보관
if body[:2] == JPEG_SOI:
    if buf:
        self.dropped += 1
        buf.clear()
    stamp = self.read_stamp(data)
...
self.publish(bytes(buf), stamp)

# ③ read_stamp()  — 새 메서드
def read_stamp(self, packet):
    if self.aux_header < 16:          # 옛 예제(index 만)엔 sec/nsec 가 없다
        return None
    sec  = int.from_bytes(packet[3:7],  'little')
    nsec = int.from_bytes(packet[7:11], 'little')
    return (sec, nsec) if 0 <= nsec < 1_000_000_000 else None

# ④ publish(self, jpeg, stamp=None)
if self.stamp_source == 'morai' and stamp is not None:
    msg.header.stamp.sec, msg.header.stamp.nanosec = stamp
else:
    msg.header.stamp = self.get_clock().now().to_msg()      # 기존 동작
```

계획보다 두 가지가 늘었다. **`stamp_source` 오타를 예외로 잡는다** — 조용히 `recv` 로 떨어지면 `slop_s=0.005` 짝짓기가 이유 없이 실패하고, 원인을 브리지에서 찾기 어렵다. **`nsec ≥ 1e9` 면 스탬프를 버린다** — 오프셋이 어긋났다는 뜻이고, 이상한 스탬프로 짝을 맞추느니 수신 시각으로 떨어지는 편이 낫다.

## 안전한가
카메라 `header.stamp` 를 쓰는 downstream 이 없다. `traffic_light_node.on_image` 는 `get_clock().now()` 로 자체 계산하고(`traffic_light_node.py:163`), `camera_view` 도 스탬프를 안 본다. 기본값 `recv` 면 바이트 단위로 기존과 동일하다.

## 같이 한 것
- `ctrl_camera/config/traffic_light.yaml` 에는 **넣지 않았다.** 기본값 `recv` 로 충분하고, 이 패키지의 `record.yaml` 에서만 `morai` 로 켠다
- `ctrl_camera/개발명세서.md` §3-1 에 파라미터 한 줄 추가 ✅

## 9-1. 종횡비 경계 — 실측으로 다시 잡았다 (2026-09-22)

| 실측 | 종횡비 | 판정 |
|---|---|---|
| 4구 `77×19` | 4.05 | ✅ 4구 |
| 4구 `87×22` | 3.95 | ✅ 4구 |
| 3구 `49×16` | 3.06 | ✅ 3구 |

명세서 §3-3 의 이론값(4구 3.43 / 3구 2.57)보다 둘 다 **19 % 크다.** 다만 둘 사이 비율은
4.05/3.06 = 1.31 로 이론의 1.33 과 맞는다 — 모양 모델은 맞았고 절대 스케일만 틀렸다.
옛 임계값(3구 ≤ 2.7, 4구 ≥ 3.3)에서는 **3구 3.06 이 경계에 걸려 4구로 판정**됐다.

경계는 두 실측의 기하평균 `√(3.06 × 3.95) = 3.48` 에 둔다.

**'모르겠다' 폭이 크기에 따라 변한다.** 높이가 1 px 흔들리면 종횡비가 `ratio/h` 만큼
움직이는데, 이게 실측 크기(h 16~22)에서는 ±0.2 지만 원거리에서는 훨씬 크다.

```
77×19 → ±0.21      49×16 → ±0.19      33×7 → ±0.69      17×4 → ±1.13
```

고정 폭으로는 원거리 박스에서 의미가 없으므로 `aspect_margin(ratio, h) = max(0.25, ratio/h)`
를 쓴다. 실측 3개는 높이가 0.9~1.5 px 틀려도 안전하고, `17×4` 같은 박스는 자동으로
`aspect_ambiguous` 가 되어 검수행으로 간다.

**못 정할 때는 4구로 둔다.** 3구를 4구로 읽으면 red·green 은 위치 오차 .045 로 그대로
맞고 yellow 만 검수행이 된다. 반대로 4구를 3구로 읽으면 **좌회전(.625)이 3구 green(.83)에
붙어 LEFT 가 GREEN 이 된다** — 좌회전 전용 신호에 직진하는 것이라 가장 위험하다.

`MERGED_BOUNDARY` 도 8.0 → 5.73 으로 내렸다. 4구 하나가 실측 4.05 라 둘이 붙으면 ≈ 8.1 인데,
옛 임계 8.0 은 그 바로 위라 여유가 없었다.

**ROI 를 좁히지 않으면 두 가지가 손해다.** `imgsz` 가 1280 으로 잡혀 8 GB 에서 `batch 4` 까지 내려가고, Roboflow 에 1280×720 원본을 올리게 돼 27×8 px 박스를 손으로 그려야 한다(명세서 §3-8 ⑤). ROI 를 정하면 `ctrl_extract.py` 가 `dataset/roi.json` 에 `imgsz` 를 써주고 `ctrl_train.py` 가 그걸 읽는다.

# 12. 수집 런치의 설정 충돌 수정 (2026-09-22 21:52 실측)

MORAI 네트워크 설정은 정상이어도 `ctrl_record.launch.py`에서만 GPS·IMU·STATUS가 모두 0이었다.
단독 `ctrl_low_speed.launch.py`에서는 수신됐다. 부모와 포함된 런치가 모두 `config` 인자를 써서,
주행 노드에 `low_speed.yaml` 대신 `record.yaml`이 전달됐다. 실제 ROS 파라미터를 읽으니
`sensor_bridge.sim_ip`가 기본값 `192.168.10.1`이었다. 이 때문에 `192.168.0.11`에서 온
패킷을 버렸다. IP뿐 아니라 localization·path_follower 설정도 누락되는 문제였다.

`ctrl_record.launch.py`에서 주행 런치에 `low_speed.yaml`을 명시하고 `GroupAction(scoped=True)`으로
감쌌다. 주행 설정이 뒤의 카메라 노드 설정까지 덮어쓰지 않게 한다. 대회 패키지 수정은 없다.

수정 후 `check:=true drive:=false view:=false` 실측:
- `sim_ip=192.168.0.11`, 카메라 포트 9208/9210 유지.
- GPS·IMU·STATUS 각각 448개 수신, 파싱 오류 전부 0, recorder에 `s=0.7` 도착.
- WAITING을 벗어나 위치·경로 확보. 이후 Auto/D handshake timeout은 `drive=false`라
  제어 명령을 보내지 않는 진단 조건에서 발생했다. **실제 주행은 아직 검증하지 않았다.**
- 현재 정차 위치의 카메라 짝 235쌍, |dt| 중앙 0 ms / p95 1 ms / 최대 2 ms.
  하늘색 영역 99.39%, 유효 신호등 박스 없음. 이 표본으로 ROI/보행자등 임계를 정하지 않았다.
  신호등이 없는 장면의 팔레트 변경 제안도 적용하지 않았다.
- 기존 62개 + 런치 설정 회귀 2개 = **64개 통과**. 회귀 테스트는 ROS 환경을 source하고
  실행하며, 노드 프로세스나 UDP 소켓을 열지 않고 실제 런치의 파라미터 전개를 검사한다.

기존 `20260922_213952_cloudy_13h` 123쌍, `20260922_214534_cloudy_13h` 9쌍은
`meta.csv`의 `s`가 전부 비어 있다. 본 수집 6회가 완료된 것으로 세거나 무조건 glob으로
학습 데이터에 포함하면 안 된다. 파일은 보존했다.


## 수집 전용 정차 (2026-09-22)

`CollectionStops.step()`은 순서대로 정지선을 골라 `stop_s`를 발행하고,
앞바퀴가 목표 ±0.5 m, 속도 ≤0.1 m/s일 때부터 기본 60초를 센다.
`CollectionStopNode`는 공유 `StopLineTable`, `/localization/s`, `/vehicle/status`를 읽고
20 Hz로 `/behavior/target`을 발행한다. 센서 단절·움직임·타이머 공백은 대기 시간을 초기화한다.
정지선을 넘기면 `v_max=0`으로 유지한다. 완료한 정지선은 같은 실행에서 다시 대기하지 않는다.

`ctrl_record.launch.py`는 정차 활성 시에만 임시 low_speed 설정에 `require_target=true`를 적용하며,
노드 종료 시 런치를 종료한다. 대회 패키지의 소스·설정은 수정하지 않는다.
`stop_seconds:=0`, `drive:=false`, `check:=true`에서는 정차 노드를 띄우지 않는다.
도우미 옵션은 `--stop-seconds`이며 기본 60이다. 조작 예시는 [사용법.md](사용법.md).
기존 제어기와 간단한 차량 모델로 20/30 km/h에서 두 정지선의 60초 정차·재출발을 검증했다.
실제 MORAI 제동·신호등 가시성은 미검증이다. 고정 시간 대기이므로 전체 신호 사이클은 보장하지 않는다.
